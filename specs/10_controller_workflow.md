# Smart Thermostat

## Thermostat Controller Workflow

Version: 1.2

Status: Frozen

---

# 1. Purpose

This document defines the execution workflow of the Thermostat Controller.

The Thermostat Controller is responsible only for orchestrating the internal domain components.

It never implements business logic.

Every decision is delegated to a specialized component.

The Thermostat Controller evaluates a Runtime Context generated by the Home Assistant integration layer.

---

# 2. Responsibilities

The Thermostat Controller SHALL:

- receive a Runtime Context;
- coordinate the execution flow;
- invoke the appropriate domain components;
- request state transitions;
- request device actions;
- produce the orchestration result.

The Thermostat Controller SHALL NOT:

- read Home Assistant entities;
- read Config Entry values;
- evaluate thermal demand;
- evaluate protection rules;
- evaluate transition rules;
- select heating sources;
- implement thermostat algorithms.

---

# 3. Inputs

The Thermostat Controller receives exactly one input:

- Runtime Context

The Runtime Context contains every runtime value required by the controller and the domain layer.

The Thermostat Controller never retrieves runtime information directly.

---

# 4. Execution Workflow

For every evaluation cycle, the Thermostat Controller SHALL execute the following steps.

---

## Step 1

Receive a Runtime Context.

---

## Step 2

Read the current logical thermostat state from the Runtime Context.

---

## Step 3

Invoke the Demand Engine.

Input:

- Runtime Context

Output:

- NO_DEMAND
- HEATING
- COOLING

---

## Step 4

If the Demand Engine returns HEATING:

Invoke the Source Engine.

Input:

- Runtime Context

Output:

- BOILER
- AIR_CONDITIONER

If the requested heating source differs from the current heating source contained in the Runtime Context:

Execute the protection workflow defined in:

specs/12_controller_protection_workflow.md

If the Demand Engine returns COOLING:

The configured Cooling Source is used.

If the Demand Engine returns NO_DEMAND:

No source selection is performed.

---

## Step 5

Determine the requested logical thermostat state.

Invoke the Transition Table.

Inputs:

- Current Thermostat State
- Current Demand

Output:

- Requested Thermostat State

The Thermostat Controller never derives transition rules.

---

## Step 6

If the requested logical thermostat state differs from the current logical thermostat state:

Invoke the Protection Engine according to:

specs/12_controller_protection_workflow.md

Input:

- Runtime Context

Output:

- ALLOWED
- DENIED

If denied:

Keep the current logical state.

If allowed:

Update the State Machine.

---

## Step 7

Generate the orchestration result.

The result SHALL contain only:

- Current Demand
- Current Heating Source
- Requested Heating Source
- Current Thermostat State
- Requested Thermostat State
- Protection Result

The result SHALL NOT contain:

- Home Assistant entities;
- Device objects;
- Service calls;
- Home Assistant types.

---

# 5. Workflow Principles

The Thermostat Controller is an orchestrator.

It never makes decisions.

Every decision is delegated to one of the following components.

| Component | Responsibility |
|-----------|----------------|
| Runtime Context Factory | Collect runtime information |
| Demand Engine | Evaluate thermal demand |
| Transition Table | Determine requested thermostat state |
| Source Engine | Select heating source |
| Protection Engine | Evaluate timing constraints |
| State Machine | Store logical thermostat state |

The Thermostat Controller coordinates these components without duplicating their responsibilities.

---

# 6. Error Handling

If any component raises an exception:

- terminate the current evaluation cycle;
- do not modify the State Machine;
- do not request device actions.

Exception handling outside the Thermostat Controller is the responsibility of the Home Assistant integration.

---

This document defines the complete execution workflow of the Thermostat Controller.

The implementation shall strictly follow this workflow.

State transitions are defined exclusively in:

- specs/11_controller_transition_table.md

Protection evaluation is defined exclusively in:

- specs/12_controller_protection_workflow.md
